# 3D 模型：原版水仙倒放导出

新增入口：**Tools → Narcissus → 3D Model Reverse Recorder**。

这条路径直接调用现有 `NarcissusFaceGrowth.UpdateRecording`，由同一个 `NarcissusColonyLayout` 和 `NarcissusModel` 生成全部 38 株植物、根系、花冠避让数据与萤火虫。没有另建螺旋布局，也没有更换花朵模型。RecordedColony 保留原 shader 的两个 fragment 函数，仅将顶点从平面贴层投影改为三维投影，使后脑能遮挡脸前的植物。

## 操作

1. 在 GitHub Desktop 获取更新并切换到 `codex/model-reverse-recording`。
2. 打开现有 Unity 项目，停止 Play。打开上述菜单。
3. `Copy live effect settings` 自动选取场景的 `MidFaceEraseMask`，也可以手动拖入原组件。使用它的花朵亮度、萤火虫亮度、皮肤重建等参数。
4. 选择原始 `human portrait 3d model.glb`，再选择随本次交付提供的 `Tripo-Unity-Calibration.json`。原始模型与标定数据通过 SHA-256 匹配，避免用错人脸。
5. 在 **Film settings / 视频设置** 填写 **Total seconds / 总时长**、**Reveal at / 开始露脸秒**、**Fade seconds / 渐显用时**、每圈秒数及 **Stop at / 停转目标秒**。填写新的开始露脸秒数后，视频采用固定总时长；露脸开始、渐显过程、停转目标和视频结束互相独立。
6. 点击 **Build / rebuild preview**，检查开头、花朵消失、最后一圈完成及最终露脸。默认对应 0 秒、10 秒、13 秒。改变参数后预览会刷新；换模型、标定文件、场景组件或布局种子后需要重新 Build。
7. 预览生成后点击 **Play / 播放**，再次点击为 **Pause / 暂停**；**Replay / 从头播放** 从第 0 秒重播。拖动进度条或修改设置会暂停，播放到片尾也自动暂停。无需进入 Unity Play 模式，预览不写图片或视频文件。
8. 确认后点击 **Export …-second film**，选择输出目录。导出会暂停预览，并逐帧完整渲染。

预览最多刷新 30 次/秒，按真实经过的时间播放；大型模型或 4K 设置下可能跳过预览帧，导出仍按所选帧率输出每一帧。

| 设置 | 选项 |
| --- | --- |
| Total seconds / 总时长 | 2–3600 整秒；使用明确的开始露脸时间后，视频严格持续到这个时间，剩余片尾保持人脸 |
| Reveal at / 开始露脸秒 | 从视频第几秒开始恢复真实脸，支持小数；不会自动等到正面或取整到整圈 |
| Actual seconds / 实际时长 | 使用新开始露脸字段时等于固定总时长 |
| Final hold / 最后保持 | 完整露脸并停转后，到视频结束之间保持正面的时间 |
| Fade seconds / 渐显用时 | 从模糊脸到真实脸需要几秒，默认 3 秒；与开始露脸时间分别填写 |
| Stop at / 停转目标秒 | 0–7200 秒，支持小数。到达该时刻后按原方向、原速度转完当前一圈再停；填 0 则从开始就不旋转 |
| Face reveal / 真实脸渐显 | 显示实际开始和完成露脸的秒数 |
| Rotation ends / 实际停转 | 显示补完当前一圈后真正停转的时间 |
| Seconds per turn / 每圈秒数 | 0.1–3600 秒，支持小数；默认 10。数值越小转得越快 |
| Resolution / 分辨率 | HD720p = 1280×720；FullHD1080p = 1920×1080；UHD4K = 3840×2160 |
| Frame rate / 帧率 | 24、25、30、60 fps |
| Format / 格式 | MP4_H264；MOV_ProRes422HQ；PNG_Sequence |
| MP4 quality / 画质 | Standard / High / Maximum（CRF 22 / 18 / 14）；MOV 固定 ProRes 422 HQ；PNG 无损 |

**采访统一转速：** 所有人使用同一个 `Seconds per turn`，只按采访长度修改 `Target seconds`。例如都填 **10**，无论目标时长是 60、83 还是 100 秒，旋转始终按 **10 秒一圈（36°/秒）**。每圈秒数默认 10，请为所有人物填写同一个数值。

**146 秒采访示例：** 总时长 **146**、开始露脸 **71**、渐显用时 **3**、每圈秒数 **10**、停转目标 **120**。花朵在第 71 秒收完；第 **71–74 秒**一边旋转一边恢复真实脸；第 **74–120 秒**真实脸继续旋转；第 **120 秒**恰好转完第十二圈，停在正面；第 **120–146 秒**保持 26 秒。30 fps 导出 **4380 帧，准确 146 秒**。

**停转继续按完整圈完成：** 停转目标不是强制回正。例如每圈 10 秒、停转目标 115 秒，会保持原方向和速度继续到 120 秒再停。开始露脸 71 秒保持不变，不会被推迟到 80 秒或 120 秒。花朵倒放在指定的开始露脸时刻完成；渐显完成后继续显示完整真实脸。

总时长是固定的，最后完整一圈必须在片尾之前完成。如果总时长 146、每圈 10 秒、停转目标 145 秒，则实际要到 150 秒才能停，窗口会指出时间冲突并暂停导出。可改停转目标为 140、调整每圈秒数，或增加总时长。开始露脸时间会限制在总时长减去渐显用时以内，以保留完整渐显。

旧项目未编辑新的开始露脸字段时保留原自动时间计算，避免已有设置突然改变。按上述示例明确填写开始露脸秒数后，启用固定总时长及片尾保持。窗口、导出按钮、文件名和 `render-info.txt` 均显示最终片长。

默认导出 1920×1080、30 fps、390 张 PNG，时长 13 秒。总时长 146 秒、30 fps 对应 4380 张 PNG。所有格式都保留完整 PNG 序列；选择视频格式时再自动编码。工具检查 Mac 常见 ffmpeg 路径，也可点击 **Choose ffmpeg (optional)** 指定已有的可执行文件。找不到 ffmpeg 时窗口提前提示，仍可导出 PNG（从 `frame_00000.png` 按选择的帧率导入剪辑软件）。编码期间设置锁定，避免另一次导出覆盖其状态。

分辨率决定输出像素数量，不能补出原模型或贴图缺失的细节；皮肤参考重建仍使用 1024×1024。PNG 为 RGB，不含透明通道。长时长和高分辨率会增加逐帧渲染时间与磁盘占用。

默认 13 秒的时间线：

- 0–10 秒：头部固定中心自转一圈，原生长时间从 21 秒倒退到 0。
- 第 10 秒：花朵、根系和萤火虫全部退去，留下原版重建皮肤。
- 10–13 秒：五官颜色与几何形状逐渐恢复。将停转目标设晚一些，就会边露脸边继续旋转；固定总时长更长时，在完成露脸及停转后保持到片尾。

布局随机种子默认 1，等同于实时场景重置后的第一个 track。实时场景本来就会为不同 track 生成不同大小、朝向和错峰时间；要复用某次特定 track 的分布，可填入相同 track ID。模型脸型与关键点仍会影响相对位置。

## 数据适配与限制

- GLB 读取器针对本次提供的未压缩、单网格、单材质、无节点变换的 Tripo 导出。其他结构明确报错。
- **更换人物必须同时更换对应的标定 JSON。** 当前工具不会自动为新模型生成标定；选择不同 GLB 会清除旧标定和旧预览，避免误导出前一个人。每个新人物需检测自己的 468 个关键点，并核对朝向、缩放、取景和面部投影深度。匹配后仍使用同一套 Unity 花朵及倒放算法，但脸型差异会影响落点，不能保证布局逐像素相同。
- 标定文件包含从该模型正面渲染检测出的 468 个关键点，不从实时摄像头采集。模型及标定文件不写入公共仓库。
- 原版皮肤重建和遮罩先在模型正面参考图上计算，再投影到三维表面。侧面深度平滑是为离线模型新增的适配，并非原实时二维遮罩的功能。
- 原版法线贴图/PBR 不用于人像：保留原始肤色图，避免照片自身光照叠加新灯光。植物保留原 shader 的光照计算。
- Live `Update` 的时钟、20 Hz 节流和跟踪路径不变。只有录制入口接受绝对时间并跳过节流。
- 工具当前是待 Unity 本机验证的版本。开发环境无 Unity 编辑器，尚未完成 Unity 编译、GPU shader、macOS 图像方向/颜色和视频成片验收；不能将托管测试通过视为 Unity 内效果已验证。

## 已完成的验证

- 预览播放时钟：验证播放、暂停、继续、拖动时暂停、从头重播、片尾自动暂停和慢帧不超出片尾；验证预览不会改变导出帧数或时间。
- 可配置时间线：验证 146 秒 / 71 秒开始露脸 / 120 秒停转 / 26 秒片尾保持，24/25/30/60 fps 的精确片长和帧数；验证明确露脸时间不随速度或停转改变、片尾保持、时间冲突、0 秒露脸和小数开始时间。保留旧设置兼容性、独立停转、最后一圈恒速顺向完成及编码参数检查。
- 视频编码：以测试 PNG 序列实际编码 H.264 MP4（720p / 25 fps）与 ProRes 422 HQ MOV（720p / 30 fps），通过 ffprobe 核对格式、像素格式、帧数和 2 秒时长。这是编码验证，不是 Unity 模型画面的验收。
- 实际 GLB 解码：983,681 个顶点、5,713,800 个索引，UV 数匹配。
- 原花朵/布局测试：20 个随机布局、花瓣外壳、附着短茎、关节变形、21 秒成熟终点通过。
- 106 项原皮肤状态和录制 seek 测试通过（托管边界替身）。
- Editor 导出代码及原生长代码通过 C# 语法/类型边界检查；此项不等于 Unity Editor 编译。
- RecordedColony 的花朵及萤火虫 fragment 函数与原 shader 文本一致。
